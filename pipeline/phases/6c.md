## OAuth callback pages (owner decision 2026-10-04: the web app owns the redirect)
- **Redirect targets:** Oura and Strava redirect the browser to `/settings/connections/<provider>/callback` on the web app. `OURA_REDIRECT_URI` and `STRAVA_REDIRECT_URI` in `.env.example` already point there.
- **What the page does:** it reads `code`, `state` (and `error`/`scope` if present) from the query, then calls the API's `GET /api/v1/connections/<provider>/callback` with the same query and the signed-in user's Bearer token. The API verifies the state, which is bound to that user.
- **After the call:** on success, redirect to `/settings/connections` with a success notice. On a provider `error` (user denied) or an API 4xx, show a clear message and a retry button.
- **Data handling:** never log or persist the `code`. Don't put it in client-side analytics or error reporting.
- **Signed-out users:** if the user isn't signed in when the browser lands on the page, send them to sign-in and return to the same URL afterwards, keeping the query.
- **Terra:** its widget already returns to `TERRA_SUCCESS_REDIRECT_URL` / `TERRA_FAILURE_REDIRECT_URL` (`/settings`), so just show its status there.
- **Tests:**
  - success forwards the exact query with the Bearer token;
  - `error=access_denied` shows the denied message without calling the API;
  - an API 400 for invalid state shows a retry;
  - the code doesn't appear in any console output.
