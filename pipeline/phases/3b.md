# Phase 3b — Terra adapter for Zepp/Amazfit (daily-metrics source)
PLAN refs: §5.3, §6, §12, §13. Build against the existing connection framework on main.
- WebFetch the current Terra docs first (widget session, webhooks, signature header, payload schemas for daily/sleep/body). Cite URLs beside each field mapping.
- Connection: backend generates a widget session with reference_id = internal user id; callback/route that records the Terra user_id in provider_connections.
- POST /api/v1/webhooks/terra: verify `terra-signature` (HMAC-SHA256 over "<t>.<raw body>", constant-time compare, reject stale timestamps) BEFORE parsing; requires the raw body, so configure the route's body parser accordingly. Record receipt in webhook_events, then normalize and upsert.
- One-time historical backfill job triggered right after connect; no ongoing poller.
Tests: valid signature accepted, tampered body rejected, wrong secret rejected, stale timestamp rejected, unknown reference_id ignored safely, normalization from fixtures.
