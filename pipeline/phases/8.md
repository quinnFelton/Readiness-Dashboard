## Lambda entrypoints (`apps/api/src/lambda/**`, with Vitest tests, AWS mocked)
Today only `apps/api/src/lambda.ts` exists and it serves the whole Express app. Add thin handlers that
reuse existing code, bundled with `NodejsFunction` (esbuild; workspace packages ship TS source):
- `api` — the REST API. `webhooks` — the provider webhook routers only, so the webhook role needs no
  more than PLAN §11 grants. If splitting needs an option on `createApp()`, request it under "Needs"
  and route both through `lambda.ts` for now.
- `oura-sync` and `oura-subscriptions` — wrap the existing handlers in `apps/api/src/providers/oura/`.
- `strava-replay` — calls `replayStravaEvents` (`apps/api/src/webhooks/strava/routes.ts`) with
  `lazyStravaIngest()`. The Strava webhook answers within 1.5 s and finishes ingest in the background;
  Lambda freezes the process after the response, so slow ingests stay `pending` and this job is what
  completes them. Schedule it every few minutes. No SQS or Step Functions (PLAN §13).
- `webhook-ttl` — deletes `webhook_events` older than a configurable number of days (default 30).
- `migrate` — applies `apps/api/db/migrations` from inside the VPC; the deploy workflow invokes it
  after the stacks are deployed. The database is not reachable from GitHub runners.

## Token encryption
`KmsTokenCipher` currently throws. Implement it as an envelope: one data key, stored KMS-encrypted,
decrypted once per cold start, then the existing `LocalAesGcmCipher` does the per-token work with the
same `context` AAD. No KMS round trip per token read. Mock KMS in tests.

## Cost and networking (PLAN §11 expects near $0/month at 11 users)
Fetch current AWS pricing and docs (WebFetch) before choosing; cite the URLs in `infra/cdk/README.md`.
- Lambdas must be in the VPC to reach Aurora and still call Oura, Strava and Terra. A managed NAT
  Gateway is a fixed monthly baseline that breaks the cost goal. Default to a small NAT instance,
  selectable by CDK context (`natMode=instance|gateway`), and avoid interface endpoints with a fixed
  hourly cost. State the trade-off in DEPLOY.md.
- Aurora Serverless v2 with min capacity 0 and auto-pause, if the engine version supports it. Note the
  resume delay and why it is acceptable: webhook events are persisted and replayed.
- Oura has webhooks (phase 3a), so the scheduled Oura sync is a daily safety net, not a frequent
  poller that keeps the database awake. Make every schedule a context value.
- Lambda env: `PG_POOL_MAX=1`. Do not put the database password in a plaintext env var; if
  `apps/api/src/users/pool.ts` needs a change to load it from Secrets Manager at cold start, describe
  the exact change under "Needs from other phases" and wire the interim in the entrypoints you own.
- The web app and the API share `NEXTAUTH_SECRET` (the web mints HS256 API tokens with it). Both must
  read the same secret.
- Amplify: pnpm monorepo build settings for `apps/web` (app root, hoisted node linker, SSR env vars).
- List every resource with a fixed monthly cost in `infra/cdk/README.md` for phase 9's docs/COST.md.
