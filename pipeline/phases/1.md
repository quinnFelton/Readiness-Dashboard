# Phase 1 — Auth & user model
PLAN refs: §2, §6 (REST surface: /auth/login, /users/me, /users), §7 `users` table, §9 auth-aware rendering, §12.
Build:
- Migration for `users` exactly as PLAN §7.
- NextAuth in apps/web with Postgres-backed sessions (email magic link or credentials for dev;
  keep the provider swappable). The API trusts a signed session/JWT from the web app — document the mechanism in apps/api/src/auth/README.md.
- RBAC middleware in apps/api: `requireUser`, `requireMaster`, and `requireSelfOrMaster(paramName)`.
- Routes: GET /api/v1/users/me, GET /api/v1/users (master only).
- apps/web/middleware.ts blocks /admin for non-master sessions (redirect + 403 from API).
- Seed script: 10 `user` + 1 `master` account with deterministic emails (`user01@example.test` … , `master@example.test`).
Tests: a user gets 403 on /users and on another user's resources; master gets 200; unauthenticated gets 401.
