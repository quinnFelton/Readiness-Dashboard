## Harness (the scaffold's config only starts `next dev`; replace it)
- Playwright must start **both** servers: the API and the web app (`next build` + `next start` in CI,
  dev server locally is fine), with `API_URL`, `NEXTAUTH_SECRET`, `TOKEN_ENCRYPTION_KEY` and provider
  env set to e2e values. A `globalSetup` migrates and seeds the database at `DATABASE_URL`.
- **Server-side provider calls cannot be mocked with `page.route`.** The OAuth code-for-token exchange,
  Strava stream fetches and the Terra widget session all run inside the API process. Start the API
  from a launcher under `tests/e2e/` that stubs outbound HTTP to the Oura, Strava and Terra hosts
  (e.g. wrap `globalThis.fetch`, or register adapters with an injected fetch before `createApp()`,
  which only registers providers that are not already registered) and fails on any other external
  host. Use `page.route` only for the browser-side redirect to the provider's authorize page / widget.
  Strava's URLs are hardcoded in `packages/provider-adapters/src/strava/client.ts`; do not edit them.
- `apps/api/db/seed` only creates accounts. Add an e2e seed under `tests/e2e/` that inserts
  `daily_metrics` and `activity_efforts` for one seeded user, then produces `trends`/`readiness_scores`
  by calling `FatigueFitnessService.onSyncComplete` rather than inserting trend rows by hand. Make it
  idempotent and limited to the seed accounts.
- Flows that mutate state (connect, disconnect) run serially or on their own user, so the suite stays
  deterministic with `fullyParallel`.

- The dashboard charts use Recharts, which unit tests mock. Flow 5 must assert that the chart actually
  renders data points for the seeded user, not only that its container exists.
